# Weatherhaven website

Production build of the redesign: Astro 5, static pages prerendered at build time, a serverless endpoint for the quote form, and the 3D viewer (three.js + Weatherhaven's TRECC CAD) loaded on demand.

## Run it

```
npm install
npm run dev        # http://localhost:4321  (includes the /api/quote/ endpoint)
npm run build      # → .vercel/output  (Vercel Build Output API)
npm run preview
npm test           # route, link and structured-data checks against a served build
npm run budget     # first-load byte budget (needs Playwright)
node scripts/a11y.mjs   # axe-core audit of the key pages
```

Deploy: `vercel` from this folder (first run creates the project), `vercel --prod` to publish. Environment variables go in Vercel → Project → Settings → Environment Variables; see `.env.example`.

## Switches (environment variables)

| Variable | What it does |
|---|---|
| `SITE_URL` | Public URL used for canonical links, sitemap and Open Graph. |
| `PUBLIC_NOINDEX=1` | Keeps search engines out (robots meta + robots.txt). Set on previews, remove at launch. |
| `RESEND_API_KEY`, `CONTACT_TO`, `CONTACT_FROM` | Quote form delivery by email (Resend). |
| `HUBSPOT_PORTAL_ID`, `HUBSPOT_FORM_GUID` | Quote form delivery to a HubSpot form instead. |
| `PUBLIC_ANALYTICS` | `plausible`, `vercel` or `none`. Both options are cookieless. |
| `PUBLIC_PLAUSIBLE_DOMAIN` | Domain registered in Plausible. |
| `PUBLIC_SENTRY_DSN` | Browser error monitoring. |
| `PUBLIC_CONSENT=1` | Shows a cookie banner (only needed if a cookie-based tool is added later). |

With no form provider set, quote requests are validated, logged in the function logs, and the visitor still sees a thank-you.

## Editing content

Everything the site says is in `src/content/*.json`. Change a product fact there and rebuild. Image keys refer to `src/generated/img.json`, which `scripts/images.py` builds from the photo folders:

```
python3 scripts/images.py <folder-with-photos> [more folders]
```

### Moving to a CMS

The JSON files are the content model. To move to Sanity, Contentful or similar: create document types with the same fields (`products`, `sectors`, `services`, `news`, `people`, `support`, `accessories`, `timeline`, `places`), import the JSON, and replace the `import ... from '../content/x.json'` lines at the top of `src/client/app.js` with a fetch in `src/lib/content.js` that runs at build time. Nothing else needs to change; the renderers only read plain objects.

## The 3D viewer

`public/assets/js/viewer3d.js` is the engine: environments, time of day, storm, the TRECC deploy, step inside, x-ray, fact pins, the camp planner's 3D view and the scroll story. It is plain JavaScript on three.js r128 and is loaded only when a page needs it (home on desktop, product pages with a model, the planner, the record page). On phones the home page shows a short clip instead and loads the engine on tap.

To add another CAD model, run it through the pipeline in the concept project (`scratchpad/glbtool/process.mjs`: weld → drop specks → simplify → crease normals → Draco), drop the GLB in `public/assets/models/`, and add a `build…`/`pose…` pair in `viewer3d.js` following `buildTrecc` / `poseTrecc`.

## Accuracy

All copy and numbers come from weatherhaven.com (see `src/content`). The TRECC geometry is Weatherhaven's CAD; the motion between packed and deployed, the forklift and the interior fly-in are illustrative and labelled as such on the page. The MECC, HERCon and Series 4 models are illustrative stand-ins built from product photos.
