# Weatherhaven website

Production build of the redesign: Astro 5, static pages prerendered at build time, a serverless endpoint for the quote form, and the 3D viewer (three.js + Weatherhaven's TRECC CAD) loaded on demand.

## Run it

```
npm install
npm run dev        # http://localhost:4321  (includes the /api/quote/ endpoint)
npm run build      # → .vercel/output  (Vercel Build Output API)
npm run preview
npm test           # route, link and structured-data checks against a served build
npm run budget     # first-load byte budget (needs Playwright)
node scripts/a11y.mjs   # axe-core audit of the key pages
```

Deploy: `vercel` from this folder (first run creates the project), `vercel --prod` to publish. Environment variables go in Vercel → Project → Settings → Environment Variables; see `.env.example`.

## Switches (environment variables)

| Variable | What it does |
|---|---|
| `SITE_URL` | Public URL used for canonical links, sitemap and Open Graph. |
| `PUBLIC_NOINDEX=1` | Keeps search engines out (robots meta + robots.txt). Set on previews, remove at launch. |
| `RESEND_API_KEY`, `CONTACT_TO`, `CONTACT_FROM` | Quote form delivery by email (Resend). |
| `HUBSPOT_PORTAL_ID`, `HUBSPOT_FORM_GUID` | Quote form delivery to a HubSpot form instead. |
| `PUBLIC_ANALYTICS` | `plausible`, `vercel` or `none`. Both options are cookieless. |
| `PUBLIC_PLAUSIBLE_DOMAIN` | Domain registered in Plausible. |
| `PUBLIC_SENTRY_DSN` | Browser error monitoring. |
| `PUBLIC_CONSENT=1` | Shows a cookie banner (only needed if a cookie-based tool is added later). |

With no form provider set, quote requests are validated, logged in the function logs, and the visitor still sees a thank-you.

## Where things live

```

src/pages/[...slug].astro   catch-all: discovers routes by crawling the rendered pages and prerenders them all (about 200 URLs; 115 are real pages, the rest open a parent page at a section and point their canonical there — src/lib/canonical.js)

src/pages/ar.astro      AR page (model-viewer, QR code)
src/pages/404.astro, robots.txt.ts
public/assets/js/       three.min.js, viewer3d.js (3D engine), fitouts.js, globe.js, GLTF/Draco loaders — classic scripts, not bundled
public/assets/models/   TRECC CAD (Draco-compressed GLB, open + stowed)
public/assets/globe/    Earth textures for the globe (NASA Blue Marble / Black Marble, public domain)
public/assets/img|fonts generated by scripts/images.py from the photo library
scripts/                images.py (image/font pipeline; reads the original concept repo, so run it there), news_images.py, thumbs.py (640px copies), og_images.py (JPG link previews), sites.py (deployment map), content_index.mjs (runs on every build), postbuild.mjs (Vercel headers and caching), budget.mjs, a11y.mjs

```

## Editing content

Everything the site says is in `src/content/*.json`. Change a product fact there and rebuild. Image keys refer to `src/generated/img.json`, which `scripts/images.py` builds from the photo folders:

```
python3 scripts/images.py <folder-with-photos> [more folders]
```

### Moving to a CMS

The JSON files are the content model. To move to Sanity, Contentful or similar: create document types with the same fields (`products`, `sectors`, `services`, `news`, `people`, `support`, `accessories`, `timeline`, `places`), import the JSON, and replace the `import ... from '../content/x.json'` lines at the top of `src/client/app.js` with a fetch in `src/lib/content.js` that runs at build time. Nothing else needs to change; the renderers only read plain objects.

## Product 3D (every system but the TRECC)

`src/lib/three/systemStage.ts` (+ `walkThrough.ts`, `gltfImageTextures.ts`) is the same three.js 0.184 stage the US site uses; `src/lib/system-models.ts` lists each model's files, fit-out, walk-in start point and AR copy (copy here is from weatherhaven.com). `src/client/systemViewer.js` is the controls: packed/deployed (the model's own deploy clip), show inside, step inside, finishes, full screen, AR link. It downloads only when the viewer nears the screen, and only on a real GPU; software WebGL gets the poster, the deploy video and the interior render. Models are Barry's round-7 web package in `public/models/<id>/`; `/ar/<id>/` pages come from `src/pages/ar/[id].astro`. To update a model, drop the new files in with the same names.

## The 3D viewer (home page, TRECC, planner)

`public/assets/js/viewer3d.js` is the engine: environments, time of day, storm, the TRECC deploy, step inside, x-ray, fact pins, the camp planner's 3D view and the scroll story. It is plain JavaScript on three.js r128 and is loaded only when a page needs it (home on desktop, product pages with a model, the planner, the record page). On phones the home page shows a short clip instead and loads the engine on tap.

To add another CAD model, run it through the pipeline in the concept project (`scratchpad/glbtool/process.mjs`: weld → drop specks → simplify → crease normals → Draco), drop the GLB in `public/assets/models/`, and add a `build…`/`pose…` pair in `viewer3d.js` following `buildTrecc` / `poseTrecc`.

## Accuracy

All copy and numbers come from weatherhaven.com (see `src/content`). The TRECC geometry is Weatherhaven's CAD; the motion between packed and deployed, the forklift and the interior fly-in are illustrative and labelled as such on the page. The MECC, HERCon and Series 4 models are illustrative stand-ins built from product photos.

## Pages added after the first build

- `/record/` — globe of all 162 sites with satellite, night and field views, a guided tour and site cards
- `/products/scale/` — every system with published dimensions, drawn to one scale, packed and deployed; each of those product pages has its own to-scale panel
- `/products/compare/?ids=a,b,c` — any two or three systems side by side, shareable
- Every product page: 3D (packed/deployed, inside, walk in), AR at `/ar/<id>/`, and a gallery with renders and a full-screen viewer
- `/buy/` — RFP checklist (from the RFP guide; send with a request, copy or download), in-stock inventory, quality, supplier information
- 29 detail pages: every sector application (`/military/c2/` …), service (`/services/repair/` …), support system (`/services/support/kitchens/` …) and two accessories, with key facts, systems used and side navigation
- `/news/` — the full archive, each article on its own page (`/news/<slug>/`)

## Open questions for Weatherhaven

- weatherhaven.com says the TRECC gives three times the floor area of its shipping footprint. Measured from the CAD, the deployed TRECC is about 2.1× (85″ → 178″ wide). The site shows the CAD dimensions without a ratio; the claim should be checked.

## Known gaps before launch

- CAD for the other products (MECC, EHMECC, HERCon, Series 4 and the rest).
- A content owner to approve copy and supply proof points, photo rights, legal pages (privacy, terms).
- Real-device testing on phones and a projector. Checked so far: an Apple M3 Pro laptop in Chrome, plus automated checks with software rendering.
- **Security advisories:** `npm audit` lists issues in Astro 5 and @astrojs/vercel 8 (one critical, five high). None can be exploited on this site: `define:vars` only passes a build-time setting, and sharp and zod only run at build time. The single serverless function only sends email. The fix is Astro 7 / @astrojs/vercel 11, two major versions, so it is a planned upgrade, not a quick patch.
- **Contact form:** it needs `RESEND_API_KEY` + `CONTACT_TO` (or the HubSpot pair) set in Vercel. Without them, the form tells the visitor nothing was sent and gives the phone number and email.
- **Logo:** weatherhaven.com only has a 658px PNG; a vector logo from marketing would sharpen the large footer wordmark.
- **Phones and computers without a GPU** get the deploy video and photos, plus an Open 3D model button, instead of loading 3D automatically.
- "Natalia Mederios" on the Company page is spelled as on weatherhaven.com; confirm.
